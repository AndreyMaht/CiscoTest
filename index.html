🖼 Правила для 9 вопросов с рисунком

№Правило
60В пакет — IP конечного получателя (ServerB). В кадр — MAC своего шлюза (RouterA).
61Самая специфичная запись → next hop → второй поиск по таблице → выходной интерфейс.
62Провод = CSMA/CD (обнаружение коллизий), Wi-Fi = CSMA/CA (предотвращение).
63Та же сеть → запись On-link; другая сеть → 0.0.0.0/0 → шлюз. Никогда 127.0.0.1 и не свой /32.
65MAC получателя нет в таблице → лавина во все порты, кроме входного.
66Статус интерфейсов + IP одной командой → show ip interface brief; версия IOS / config register → show version; MAC-таблица → show mac-address-table.
67/27 = 32 адреса, 30 полезных. (30 − занятых) × число подсетей.
68Обжимка RJ-45: расплетённые жилы слишком длинные, оболочка не зажата в разъёме.
87Запрос к серверу имён = nslookup. ipconfig /displaydns — только локальный кэш.

⚠️ 8 ловушек, на которых теряют баллы

№Ловушка → правильно
3«бо́льшая пропускная способность / невосприимчив к EMI» → в этом вопросе верно «передаёт сигналы на гораздо бо́льшие расстояния»
11«адресное пространство IPv6 в 4 раза больше» ✗ → заголовок IPv6 проще → лучше обработка пакетов
14«генерируют данные», «интерфейс между людьми и сетью» ✗ (это конечные устройства) → направляют путь данных + соединяют хосты с сетью
16«два шага» → hostname + ip domain-name, ключи RSA. «три шага, учётка уже есть» → domain-name + ключи + transport input ssh
42Префикс — 2001:DB8:BC15:A, а не ::/64 в конце (автопроверка строки)
54ipconfig — сетевые настройки · route print — маршруты · tracert — путь · arp -a — ARP · ipconfig /displaydns — кэш DNS
56Ключ v5.1/v6.0 — «передающий узел вставляет стартовые и стоповые биты»; если вместо него вариант про преамбулу/SFD или кодирование — бери его (версия v7)
29«отправляется всем хостам» ✗ — это broadcast. Multicast: группе подписчиков, маршрутизаторы обмениваются маршрутами, хосты явно присоединяются
